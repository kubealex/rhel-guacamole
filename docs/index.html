RHEL Guacamole

Browser-based remote desktop for RHEL, powered by Apache Guacamole and Podman

RHEL 10 Guacamole 1.6.0 Podman (Rootless) RDP + SSH

What is this?

A complete guide to deploying Apache Guacamole on RHEL using rootless Podman containers, and configuring RHEL workstations as RDP targets with GNOME Remote Desktop. Access your Linux desktops and servers from any browser — no client software needed.

🌐

Browser-Based

Access remote desktops from any modern browser — no plugins or client installs.

🔒

Rootless Containers

All services run as unprivileged Podman containers for better security.

🖥

RDP & SSH

Connect to graphical GNOME desktops via RDP or headless servers via SSH.

🗂

Persistent Config

PostgreSQL stores users, connections, and preferences across restarts.

Architecture

  Browser
     |
     v
  Guacamole Web App :8080        <-- Guacamole Server
     |
     v
  guacd :4822
     |
     +------ RDP :3389 -------> RHEL Workstation   <-- Client (GNOME Remote Desktop)
     |
     +------ SSH :22 ---------> RHEL Server
     |
     v
  PostgreSQL
ⓘ
Two parts to configure: The Server tab covers deploying Guacamole itself. The Client tab covers preparing a RHEL workstation to accept incoming RDP connections.

Guacamole Server Setup

Deploy Apache Guacamole 1.6.0 on RHEL using rootless Podman. Three containers — PostgreSQL, guacd, and the Guacamole web app — all on a private container network.

1

Install Podman

bash
sudo dnf install -y podman

mkdir -p ~/guacamole
cd ~/guacamole
2

Create the Container Network

All Guacamole components use this private network. Only the web interface is published externally.

bash
podman network create guac-net
3

Generate the PostgreSQL Schema

bash
podman run --rm docker.io/guacamole/guacamole:1.6.0 \
  /opt/guacamole/bin/initdb.sh --postgresql > initdb.sql

Verify with ls -lh initdb.sql

4

Start PostgreSQL

Create persistent storage and start the database:

bash
podman volume create guac-pgdata

podman run -d \
  --name guac-postgres \
  --network guac-net \
  -e POSTGRES_DB=guacamole_db \
  -e POSTGRES_USER=guacamole_user \
  -e POSTGRES_PASSWORD='CHANGE_ME_DB_PASSWORD' \
  -v guac-pgdata:/var/lib/postgresql/data:Z \
  -v ./initdb.sql:/docker-entrypoint-initdb.d/initdb.sql:ro,Z \
  docker.io/library/postgres:16
⚠
Replace CHANGE_ME_DB_PASSWORD with a strong password. The initialization scripts only execute when the data directory is empty.
5

Start guacd

The Guacamole connection proxy. Port 4822 stays internal to the container network.

bash
podman run -d \
  --name guacd \
  --network guac-net \
  docker.io/guacamole/guacd:1.6.0
💡
For verbose logging, add -e LOG_LEVEL=debug to the command.
6

Start Guacamole

bash
podman run -d \
  --name guacamole \
  --network guac-net \
  -e GUACD_HOSTNAME=guacd \
  -e POSTGRESQL_HOSTNAME=guac-postgres \
  -e POSTGRESQL_DATABASE=guacamole_db \
  -e POSTGRESQL_USERNAME=guacamole_user \
  -e POSTGRESQL_PASSWORD='CHANGE_ME_DB_PASSWORD' \
  -p 8080:8080 \
  docker.io/guacamole/guacamole:1.6.0

Verify all three containers are running:

bash
podman ps

Expected: guac-postgres, guacd, guacamole

7

Access Guacamole

Open your browser and navigate to:

url
http://<GUACAMOLE_SERVER>:8080/guacamole/

Default credentials:

Username: guacadmin Password: guacadmin
🛑
Change the default password immediately after your first login.
8

Create an RDP Connection

Navigate to Settings → Connections → New Connection and configure:

FieldValue
NameRHEL Workstation
ProtocolRDP
Hostname<RHEL_WORKSTATION_IP>
Port3389
Usernamerdpuser
Password<RDP_GATEWAY_PASSWORD>
ⓘ
These are the GNOME Remote Desktop gateway credentials, not the Linux user's credentials. If using a self-signed certificate, enable Ignore server certificate.

Authentication Flow

Guacamole
▼ rdpuser / RDP gateway password ▼
GNOME Remote Desktop
▼
GDM Login Screen
▼ sysadmin / Linux password ▼
GNOME Desktop
9

Persistence

All configuration and users are stored in PostgreSQL. The guacamole and guacd containers can be recreated without data loss, as long as the PostgreSQL volume is retained.

bash
podman volume inspect guac-pgdata

For deployments that must survive logout:

bash
sudo loginctl enable-linger $USER
💡
For production deployments on recent RHEL versions, consider managing containers using Podman Quadlet/systemd.

RHEL Workstation Client Setup

Configure a RHEL 10 workstation for GNOME Remote Desktop Remote Login. This allows RDP clients (including Guacamole) to reach the GDM login screen even when no user is logged in. 

  RDP Client
      |
      | TCP/3389
      v
  GNOME Remote Desktop (system daemon)
      |
      | RDP gateway authentication
      v
  GDM
      |
      | Linux authentication
      v
  GNOME Wayland session → PipeWire → Remote Desktop
1

Install Required Components

bash
sudo dnf install -y \
  gdm \
  gnome-shell \
  gnome-session \
  gnome-remote-desktop \
  freerdp \
  pipewire \
  pipewire-pulseaudio \
  wireplumber

Enable graphical boot and GDM:

bash
sudo systemctl set-default graphical.target
sudo systemctl enable --now gdm.service
2

Create the TLS Certificate

bash
sudo mkdir -p /etc/gnome-remote-desktop

sudo openssl req \
  -x509 \
  -newkey rsa:3072 \
  -nodes \
  -days 825 \
  -subj "/CN=$(hostname -f)" \
  -keyout /etc/gnome-remote-desktop/rdp-tls.key \
  -out /etc/gnome-remote-desktop/rdp-tls.crt

Set ownership for the GNOME Remote Desktop daemon:

bash
sudo chown gnome-remote-desktop:gnome-remote-desktop \
  /etc/gnome-remote-desktop/rdp-tls.crt \
  /etc/gnome-remote-desktop/rdp-tls.key

sudo chmod 644 /etc/gnome-remote-desktop/rdp-tls.crt
sudo chmod 600 /etc/gnome-remote-desktop/rdp-tls.key

sudo restorecon -RFv /etc/gnome-remote-desktop

Verify the daemon can read them:

bash
sudo runuser -u gnome-remote-desktop -- \
  openssl x509 -in /etc/gnome-remote-desktop/rdp-tls.crt \
  -noout -subject -dates

sudo runuser -u gnome-remote-desktop -- \
  openssl pkey -in /etc/gnome-remote-desktop/rdp-tls.key \
  -noout -check
✅
The private-key test should report Key is valid
3

Configure Remote Login

bash
# Set TLS certificate and key
sudo grdctl --system rdp set-tls-cert /etc/gnome-remote-desktop/rdp-tls.crt
sudo grdctl --system rdp set-tls-key /etc/gnome-remote-desktop/rdp-tls.key

# Set RDP gateway credentials
sudo grdctl --system rdp set-credentials rdpuser 'CHANGE_ME_RDP_PASSWORD'

# Configure and enable RDP
sudo grdctl --system rdp disable-view-only
sudo grdctl --system rdp disable-port-negotiation
sudo grdctl --system rdp enable

# Start the daemon
sudo systemctl enable --now gnome-remote-desktop.service
sudo systemctl restart gnome-remote-desktop.service
⚠
rdpuser is an RDP gateway credential managed by GNOME Remote Desktop. It does not need to exist in /etc/passwd.
4

Configure PipeWire for the Linux User

GNOME Remote Desktop uses PipeWire for the desktop stream. Run as the Linux user (e.g. sysadmin):

bash
systemctl --user enable --now \
  pipewire.socket \
  pipewire-pulse.socket \
  wireplumber.service

Verify:

bash
systemctl --user status pipewire.socket pipewire.service wireplumber.service
ps -ef | grep -E '[p]ipewire|[w]ireplumber'
ls -l "$XDG_RUNTIME_DIR/pipewire-0"

Configuring from root (remote provisioning)

bash
UID_SYSADMIN=$(id -u sysadmin)
RUNTIME="/run/user/$UID_SYSADMIN"

runuser -u sysadmin -- env \
  XDG_RUNTIME_DIR="$RUNTIME" \
  DBUS_SESSION_BUS_ADDRESS="unix:path=$RUNTIME/bus" \
  systemctl --user enable --now \
    pipewire.socket \
    pipewire-pulse.socket \
    wireplumber.service
5

Verify RDP

bash
sudo grdctl --system status
sudo ss -lntp | grep ':3389'
sudo journalctl -u gnome-remote-desktop.service -n 50 --no-pager

A successful startup shows RDP server started in the journal.

💡
The message Init TPM credentials failed... using GKeyFile as fallback is harmless on VMs without a TPM.
6

Login

Connect with your RDP client:

FieldValue
Host<RHEL_WORKSTATION>
Port3389
Usernamerdpuser
Password<RDP_GATEWAY_PASSWORD>

Then authenticate at GDM with your Linux credentials.

Complete Authentication Flow

RDP Connection
▼ rdpuser ▼
GNOME Remote Desktop
▼
GDM
▼ sysadmin / Linux password ▼
GNOME User Session

Troubleshooting

Guacamole Server

SymptomCheckCause / Action
Guacamole UI unavailable podman ps Verify the guacamole container is running and port 8080 is published
Guacamole fails to start podman logs guacamole Check PostgreSQL and guacd environment variables
Database errors podman logs guac-postgres Verify schema initialization and DB credentials
RDP connection fails immediately podman logs guacd --tail 50 Check target hostname, port 3389, and RDP gateway credentials
RDP connection times out Test network connectivity from Guacamole host Target port 3389 may not be reachable
Certificate validation error Enable Ignore server certificate Expected with self-signed GRD certificate
Need more RDP detail Run guacd with LOG_LEVEL=debug Inspect FreeRDP negotiation and auth errors

RHEL Client (GNOME Remote Desktop)

SymptomCheckCause / Fix
3389 not listening grdctl --system status Ensure RDP is enabled
TLS certificate/key not configured ls -l /etc/gnome-remote-desktop/rdp-tls.* GRD daemon cannot read the certificate/key
TLS key owned by root:root systemctl show gnome-remote-desktop -p User Change ownership to gnome-remote-desktop:gnome-remote-desktop
GRD active but no RDP listener journalctl -u gnome-remote-desktop Usually incomplete TLS configuration
GDM does not appear systemctl status gdm Install/enable GDM and graphical target
Login succeeds but RDP disconnects Search journal for Couldn't connect pipewire context User PipeWire session is not running
No /run/user/<UID>/pipewire-0 Check PipeWire user services PipeWire has not started for that user
TPM credentials failed (fallback) None required Informational on systems without a TPM
Need complete diagnostics journalctl -b | grep -E 'gnome-remote|pipewire|wireplumber' Correlate GRD handover with user-session startup
